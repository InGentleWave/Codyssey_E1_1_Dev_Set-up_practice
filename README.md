## 1. 프로젝트 개요

- 목표: 터미널, Docker, Git/GitHub를 직접 세팅하고, 웹 서버를 Dockerfile로 컨테이너화하여 포트 매핑, 바인드 마운트, 볼륨으로 변경 반영과 데이터 영속성을 검증한다.
- 학습 목표
  - 절대 경로와 상대 경로의 차이를 설명한다.
  - 파일 권한(r/w/x)과 755, 644 표기를 해석한다.
  - 기존 Dockerfile을 기반으로 커스텀 이미지를 만든다.
  - 포트 매핑이 필요한 이유를 설명한다.
  - Docker 볼륨의 개념을 설명한다.
  - Git과 GitHub의 역할 차이를 설명한다.
- 보너스 과제(선택): (수행 여부 기록)

### 9-1. 바인드 마운트 반영

- [ ] 호스트 파일 변경 전/후 내용 비교
- [ ] 변경이 컨테이너에 반영되었음을 확인

### 9-2. Docker 볼륨 영속성 검증
  [결과](./evidences/command-log.md#9-2-docker-볼륨-영속성-검증)

- [ ] 삭제 전 데이터 준비
  - [ ] 볼륨 생성 명령과 출력 기록, 볼륨 목록 확인
  - [ ] 볼륨을 컨테이너 연결 명령 및 출력 기록
  - [ ] 볼륨을 연결한 컨테이너 실행, 내부에서 데이터 생성 기록
  - [ ] 컨테이너 상세 정보에서 볼륨 마운트 항목(볼륨 이름, 컨테이너 내부 경로)이 표시되는 출력 기록
  - [ ] 삭제 대상 컨테이너의 ID와 이름 기록
  - [ ] 컨테이너 삭제 전 데이터 확인 기록 (데이터 값 또는 파일 내용 원문 포함)
- [ ] 컨테이너 삭제 명령과 출력 기록
- [ ] 삭제 후 데이터 준비
  - [ ] 컨테이너 삭제 직후 볼륨 목록에 해당 볼륨이 남아 있는지 확인 기록
  - [ ] 컨테이너 삭제 후 같은 볼륨을 연결한 새 컨테이너 실행
- [ ] 삭제 전/후 데이터 유지 검증
  - [ ] 새 컨테이너의 ID가 삭제된 컨테이너의 ID와 다름을 기록
  - [ ] 새 컨테이너에서 삭제 전과 동일한 데이터 확인 기록 (삭제 전 기록과 대조)
  - [ ] 볼륨을 연결하지 않은 대조용 컨테이너에서 같은 경로를 확인하여 데이터가 없음을 기록
- [ ] 검증 종료 후 테스트 볼륨 정리 명령과 출력 기록
